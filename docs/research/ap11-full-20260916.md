iOS 27.0, concurrent camera capture, full local recording paced at real time.

**Device performance passed. Recognition agreement needs recovery work.**

returned failure for event differences. Do not describe that command as passing.

The last ten minutes did not show a processing slowdown: median 159 ms,
p95 233 ms, compared with 217/298 ms for the first ten minutes. These are
different video sections, not a controlled thermal comparison. There was no
accumulating scheduling backlog. Two analyses per second is a supported initial
budget for this workload on AP11. This includes prerecorded-video decoding and
research diagnostics, but excludes production preview/UI/persistence and future
final-score recognition. It does not establish an entire evening's behavior.

## Recognition differences

- 37 of 38 expected turn starts and all 12 mode starts were detected. Diagnostic
  matching by event kind, machine slot/ball or mode name, and nearby source time
  paired 49 events with no extras. Mode counting remains outside product scope.
- Twelve emitted events had unknown ownership after geometry loss: nine turn
  events and three mode events. They were not assigned to the wrong person.
- Four paired events confirmed 1–2 seconds earlier than the saved Mac run.
  Confirmation delay within this AP11 run was 0.5–2.502 seconds, median one
  second. Earlier confirmation is a baseline difference, not by itself an
  accuracy defect. No baseline thresholds were relaxed to manufacture a pass.

### Recovery after movement, 38:46–38:59

Both runs lost geometry on the same 13 sampled frames, 2326.095–2332.095 s.
AP11 reacquired geometry but produced no identity-recovery record.

At 2323.593 s, just before movement, Mac OCR read
`28,841,440173,594,990`. AP11 read `28,841,44° 173,594,990`.
The strict number parser therefore lost the unchanged 28,841,440 score on AP11.
After movement, the scoreboard read `28,841,440 212,386,990`.
The current detector retains only the latest parsed scoreboard-number set;
there was no shared number to satisfy its identity-recovery condition.

AP11 had correctly read 28,841,440 at 2266.093 and 2266.593 s. This supports
testing a stable, context-bound score witness across transient OCR errors.
It does not justify guessing a digit, retaining anchors across unrelated
games, or guessing player identity after arbitrary loss.

### Last turn near 51:31

The missing event is game 7, ball 1, machine player 2, expected at 3091.115 s.
AP11 recorded only two resolved player-2 observations before the recording
ended, insufficient for the existing three-observation confirmation rule.
The Mac trace resolved more observations in the same interval.

Original movie frames at 3091.115 and 3093.615 s were visually inspected.
The display is unobstructed and shows BALL 1, 162,000 on the left and the large
active zero on the right. This discrepancy is separate from the known obscured
final score. The precise cause of intermittent active-slot resolution still
needs an image-level check; the recording ending also limits recovery time.

Andreas recalls his friend blocking a final score while photographing it.
Unobservable scores must remain unknown and are not recognition failures.
The existing audited unknown score, game 2 / slot 2, remains excluded from
readable-score accuracy expectations. This native benchmark does not yet emit
final-score results at all.

## Next checkpoint

Keep the initial 2 Hz budget. Andreas accepts occasional misses at this level
if the UX makes tracking problems noticeable and easy to correct. The first
usable version must include visible uncertainty and a compact current-player/
ball correction that restores tracking while preserving scores. Test that
recovery against this run's ownership loss. Exact baseline agreement is a
diagnostic target, not a release gate for an assisted session.

Integrate this recovery flow with live alignment, final-score capture and session
state. Preserve the AP11 observations for focused automatic-recovery and
active-zero detection improvements. Do not spend this checkpoint optimizing an
already adequate runtime or chasing perfect detection at the expense of usable
recovery.
